# 코드 작성단

작성단은 확인단에서 확정한 영향 범위 안에서 가장 작은 변경을 만든다.

## 작성 흐름

```text
작업 계획
→ 실패 조건 정의
→ 필요한 테스트·검증 기준 작성
→ 최소 구현
→ 주변 코드와 연결
→ 변경 범위 재확인
```

## 작성 원칙

- 기존 구조와 패턴을 우선 재사용한다.
- 요청되지 않은 추상화와 설정을 추가하지 않는다.
- 하나의 파일과 함수에 여러 책임을 섞지 않는다.
- 도메인 경계를 넘는 의존성을 최소화한다.
- 공개 API, 타입, 환경 변수 변경은 명시적으로 기록한다.
- 입력 검증, 권한, 보안 처리를 생략하지 않는다.
- 코드 변경에 필요한 테스트를 함께 변경한다.
- 구현과 문서가 달라지면 같은 변경에서 정리한다.

프론트엔드는 가독성·예측 가능성·응집도·결합도를 기준으로 판단한다. 백엔드는 DDD 경계·인증·권한·CORS·API 계약을 중심으로 판단한다.
