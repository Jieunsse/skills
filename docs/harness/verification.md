# 검증단

검증단의 목적은 테스트 통과를 확인하는 데 그치지 않고, 변경이 안전하다는 근거를 남기는 것이다.

## 검증 게이트

```text
Gate 1  형식·정적 분석
Gate 2  타입·컴파일
Gate 3  단위 테스트
Gate 4  통합·계약 테스트
Gate 5  빌드·패키징
Gate 6  변경 diff 검토
Gate 7  문서·환경·보안 검토
```

기본 검증은 프로젝트와 변경에 해당하는 Gate 1, 2, 3, 5, 6, 7을 포함한다. 타입체크나 빌드처럼 대상이 없는 게이트는 무조건 생략하지 말고 해당 없음 사유를 기록한다. Gate 4는 API·DB·외부 시스템 또는 계층 간 연결이 변경될 때 필수로 승격한다.

검증 게이트에서 실패하면 다음 게이트로 진행하지 않고 작성단으로 돌아간다.

## 위험 우선순위

```text
데이터 손실·권한 우회
→ 기존 기능 회귀
→ API·타입·DB 계약 변경
→ 비동기 상태·에러 처리
→ 환경별 동작 차이
→ 사용자 흐름
→ 스타일·포맷
```

## 검증 결과 기록

```text
실행한 명령
대상 범위
성공·실패 여부
실패 원인
미실행 검증
남은 위험
```

실행하지 못한 검증은 성공으로 간주하지 않는다. 예를 들어 로컬 DB가 없어 e2e를 실행하지 못했다면 그 사실과 남은 위험을 기록한다.
