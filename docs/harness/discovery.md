# 코드베이스 확인단

코드베이스 확인단의 목적은 구현 속도가 아니라 잘못된 가정으로 코드를 수정하지 않는 것이다.

## 입력과 출력

입력은 사용자 요청, 저장소, 프로젝트 지침, 기존 문서다. 출력은 `Discovery Report`다.

## 확인 순서

```text
프로젝트 지침
→ 디렉터리 구조
→ 실행 진입점
→ 도메인·모듈 경계
→ 데이터·API 흐름
→ 테스트 구조
→ 최근 변경 내역
→ 작업 영향 범위
```

## 확인 항목

- 루트와 하위 디렉터리의 `AGENTS.md`, `CLAUDE.md`, 규칙 파일
- 루트 및 계층별 `docs`
- 패키지 매니저, 실행 명령, 빌드 명령
- 애플리케이션 진입점과 주요 의존성
- 모듈·도메인 경계와 의존 방향
- 상태 관리, 데이터 fetching, API 계약
- 환경 변수와 외부 서비스 연결
- 기존 테스트와 테스트 실행 명령
- 최근 커밋과 현재 작업 트리의 미완성 변경
- 수정 대상의 호출자·소비자와 예상 회귀 범위

## 작성 전 산출물

```text
작업 목적
영향받는 파일·모듈
변경하지 않을 영역
재사용할 기존 구현
필요한 검증 방법
```

## 종료 조건

- 작업 목적과 범위가 명확하다.
- 관련 규칙과 문서를 확인했다.
- 수정 대상과 비대상 영역을 구분했다.
- 재사용할 구현과 예상 위험을 확인했다.
- 검증 방법을 정했다.
- 미결정 사항이 없거나 사용자에게 전달했다.

확인단에서는 코드 수정을 시작하지 않는다. 구현 중 새로운 영향 범위나 규칙 충돌이 발견되면 확인단으로 돌아가 보고서를 갱신한다.

도메인 용어가 모호하거나 문서와 코드가 충돌하거나 검증 기준이 없으면 구현 전에 그 불일치를 해결한다.
