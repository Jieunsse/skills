# 검증 매트릭스

필수 검증은 모든 변경에 적용하고, 선택 검증은 변경 유형과 위험도에 따라 추가한다.

## 공통 기준

| 구분 | 검증 | 기준 |
| --- | --- | --- |
| 필수 | 포맷·정적 분석 | 포맷 오류와 lint 오류가 없다 |
| 필수 | 타입·컴파일 | 타입 오류와 컴파일 오류가 없다 |
| 필수 | 관련 단위 테스트 | 변경 영역과 직접 연결된 테스트가 통과한다 |
| 필수 | 빌드·패키징 | 배포 가능한 산출물이 생성된다 |
| 필수 | diff 검토 | 의도하지 않은 파일·비밀정보·디버그 코드가 없다 |
| 필수 | 문서·환경·보안 검토 | 문서, env example, 권한 처리가 구현과 일치한다 |

## 변경 유형별 선택·승격 기준

| 변경 유형 | 추가 검증 | 적용 기준 |
| --- | --- | --- |
| UI 컴포넌트 | Storybook, 시각 검증, 접근성 검사 | 공용 컴포넌트 또는 복잡한 상태 변경 |
| 사용자 흐름 | 통합 테스트, e2e | 여러 화면·API·상태가 연결됨 |
| API 변경 | 계약 테스트, 통합 테스트 | 요청·응답·에러 형식 변경 |
| 인증·권한 | 실패 케이스, 권한 경계, 회귀 테스트 | 로그인·토큰·역할·보호 리소스 변경 |
| DB·마이그레이션 | 적용·재적용·데이터 영향 검증 | 스키마·제약조건·마이그레이션 변경 |
| 환경 변수 | 누락·환경별 설정 검증 | 새 변수 추가 또는 배포 설정 변경 |
| 모노레포 설정 | 영향 패키지 검사, 전체 빌드 | workspace·Turborepo·공유 패키지 변경 |
| 배포 설정 | dry-run, 환경별 빌드 | CI/CD·Vercel·AWS 설정 변경 |
| 외부 연동 | sandbox 또는 mock 통합 검증 | MCP·결제·알림·외부 API 변경 |

## 승격 규칙

- 데이터 손실, 보안, 인증, 권한 관련 변경은 관련 선택 검증을 필수로 승격한다.
- 변경된 계약의 소비자를 확인할 수 없으면 영향 범위를 넓혀 통합 검증을 실행한다.
- 필수 검증을 실행할 수 없으면 완료로 표시하지 않고 미실행 사유와 위험을 남긴다.
- 같은 유형의 회귀가 반복되면 선택 검증을 해당 프로젝트의 필수 검증으로 승격한다.
