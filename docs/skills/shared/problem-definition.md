# problem-definition

## 분류

공통 문제 구조화 스킬. 제품 기획과 개발 계획의 선행 단계에서 사용할 수 있다.

## 목적

모호한 주제나 요구를 조사해 증상, 구조적 원인, 영향을 받는 사람, 현실과 목표의 차이를 분리하고 검토 가능한 문제 브리핑으로 만든다.

## 핵심 개념

```text
P-code    증상·목표·제약·원인 후보
R-code    표면 대응·우회책·임시 완화
KP-code   여러 증상을 설명하는 킹핀 문제 후보
S-code    킹핀 문제를 직접 해결하는 원리·구조·해결안
```

`KP-1`은 확정된 사실이 아니라 사용자가 확인해야 하는 핵심 문제 가설이다. `R-code`와 `S-code`를 혼동하지 않는다.

## 기본 흐름

```text
주제 수신
→ 문제 조사
→ 영향 사용자와 현실-목표 괴리 확인
→ P/R 코드 작성
→ KP-1 후보 선정
→ 사용자 확인
→ 필요한 경우 S-code 탐색
```

해결책을 문제로 위장하지 않으며, 답이 문제의 범위·사용자·추천을 바꿀 때만 확인 질문을 한다.

## 기본 결과물

```text
# 문제정의 브리핑
## 입력된 주제
## 핵심 결론
## 현재 상황
## 영향을 받는 사용자
## 현실과 목표의 괴리
## 현재 대응과 남은 문제
## 킹핀 후보
## 판단 상태
## 확인이 필요한 질문
```

## 연결

- `docs/loops/`: 문제 정의 루프와 계획 루프
- `docs/compositions/`: 프로젝트 시작 전 문제 범위 확정

외부 자료를 사용할 때는 사용자 제공 정보, 출처 기반 사실, 추론, 미검증 가설을 구분한다.
