# archify

## 분류

공통 시각화·아키텍처 스킬. 프론트엔드, 백엔드, 모바일, 인프라와 업무 흐름에 걸쳐 사용할 수 있다.

## 목적

아키텍처, 워크플로, 시퀀스, 데이터 흐름, 라이프사이클·상태 전이를 검토 가능한 다이어그램으로 표현한다.

## 지원 유형

```text
architecture   컴포넌트·서비스·인프라·보안 경계
workflow       프로세스·승인·도구 호출·CI/CD
sequence       API 호출·요청 수명주기·비동기 흐름
dataflow       ETL/ELT·데이터 계보·소비자 흐름
lifecycle      상태·재시도·대기·종료 전이
```

## 사용 원칙

- 실제 코드나 요구사항에 근거해 의미를 작성한다.
- 다이어그램 유형을 먼저 선택한다.
- 하나의 명확한 주 경로와 필요한 보조 흐름만 표현한다.
- 생성물은 검증 가능한 독립 HTML 다이어그램으로 취급한다.
- 렌더링이나 출력 형식보다 의미와 관계를 먼저 확정한다.
- 실제 아키텍처를 표현할 때는 추측과 확인된 사실을 구분한다.

## 연결

- `docs/skills/product/`: 문제·제품 구조를 시각화
- `docs/skills/design/`: Figma와 UI·컴포넌트 구조를 보조
- `docs/loops/`: 설계 검토와 아키텍처 리뷰 루프
- `docs/pipelines/`: CI/CD·데이터·업무 흐름 표현
- `harness/mcp/`: Figma 등 외부 컨텍스트 연결

## 관리 범위

현재 저장소에는 스킬의 목적과 사용 규칙만 기록한다. 실제 Archify 실행 파일이나 생성 결과물은 이 저장소에 포함하지 않는다.
